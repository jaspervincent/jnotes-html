US3

数据迁移

UCloud 没有控制台一键的「跨账号迁移」功能。你这个场景（A 账号 bs-os → B 账号 bs-os-test）有三条可行路径，按数据规模选：

方案 适用 特点
rclone（走 US3 的 S3 兼容协议） 几百 GB ~ 数 TB，文件数千万以内 最快上手，单机/多机并发，增量好做
US3SYNC（UCloud 官方迁移工具） TB~PB、亿级文件 master+worker 可横向扩，官方支持 US3→US3
镜像回源 需要零停机切换 只迁"被访问过"的文件，必须配合上面两者做全量

注意： us3cli cp us3://a us3://b 在这里用不了 —— 它的跨 bucket 复制仅限同账号同地域（一套 AK/SK），跨账号不行。

前置准备（两条路都要做）

  1. A 账号：控制台 → API 密钥，拿到公钥/私钥（或给 bs-os 单独建一个只读 Token）。若用子账号，务必确认已开启 API 密钥权限。
  2. B 账号：同样拿密钥，并先手动创建好 bs-os-test，地域尽量和 bs-os 保持一致。
  3. 确认两个 bucket 的地域，endpoint 不同：
    • 原生域名：cn-bj.ufileos.com / cn-sh2.ufileos.com / cn-gd.ufileos.com / hk.ufileos.com …
    • S3 兼容域名要加 s3- 前缀：s3-cn-bj.ufileos.com、s3-cn-sh2.ufileos.com …
  4. 检查存储类型：源端若有归档（Archive）对象，必须先解冻，US3SYNC 明确不支持归档源文件直迁。
  5. 准备一台中转机（建议放 A 账号同地域云主机，带宽拉满）。跨账号必然走公网，A 账号会产生外网下行流量费，先估一下成本。

方案一：rclone（推荐先试这个）

rclone 1.74.0 起内置了 US3 provider（老版本用 provider = Other）。 

vim ~/.config/rclone/rclone.conf：

[us3-a]
type = s3
provider = US3
access_key_id = <A账号公钥>
secret_access_key = <A账号私钥>
endpoint = s3-sg.ufileos.com
region = sg
chunk_size = 8M
acl = private

[us3-b]
type = s3
provider = US3
access_key_id = <B账号公钥>
secret_access_key = <B账号私钥>
endpoint = s3-hk.ufileos.com
region = hk
chunk_size = 8M
acl = private

chunk_size = 8M 不是随便填的 —— US3 的 S3 协议分片大小固定 8M，填别的值分片上传会失败。

验证 + 全量迁移： 

rclone lsd us3-a:                    # 能列出 bs-os 说明密钥和 endpoint 对了
rclone size us3-a:bs-os              # 记下对象数和总大小，最后用来对账

rclone copy us3-a:bs-os us3-b:bs-os-test \
  --transfers 32 --checkers 64 \
  --s3-upload-concurrency 4 \
  --progress --stats 30s \
  --log-file=/var/log/us3-mig.log --log-level INFO

#用 copy 不用 sync：sync 会删掉目的端多余文件，首次迁移没必要承担这个风险。
#切换前跑一次增量，同一条命令重跑即可，rclone 按 size+mtime 跳过已传的。

#校验：
rclone check us3-a:bs-os us3-b:bs-os-test --size-only

#必须加 --size-only：US3 分片上传的 ETag 不是文件 MD5，两端 hash 对不上，不加会误报一片 differ。

PS: 一个关键认知：跨 remote（不同账号、不同密钥）rclone 做不了服务端直传，数据是「下载到中转机 → 再上传」，所以中转机的带宽就是迁移速度上限。数据量大的话多开几台机器，按 key 前缀分片并行跑（–include "a*"、–include "b*" …）。

方案二：US3SYNC（大规模走这条）

官方工具，支持源端为 S3 / OSS / 七牛 / 又拍 / US3 / NAS / 本地目录 / URL 列表，目的端为 US3。

架构是 master（单点，拉源端文件列表并派发任务）+ worker（可多台横向扩，负责下载并上传），内部用 pika 做缓存，数据不落盘、按分片粒度并发 —— 这是它相对老版 ufile-import（要求磁盘 > 数据总量）的主要优势。

大致流程：

  1. 从 UCloud 文档中心下载 US3SYNC 包，目录结构为 bin/（master、worker）、conf/config.toml、cert/、log/、pika/、console.sh。
  2. 改 conf/config.toml，配置 master/worker 地址、pika 等。
  3. ./console.sh 启动，打开自带 Web 控制台。
  4. 在控制台建迁移任务：
    • 源端：类型选 US3，填 A 账号的公私钥、bucket bs-os、对应 endpoint、前缀（空=全量）
    • 目的端：填 B 账号的公私钥、bucket bs-os-test、目的前缀
    • 覆盖策略：全覆盖 / 条件覆盖（按时间戳或大小）/ 不覆盖 —— 做增量时选条件覆盖
  5. 先用一个小前缀试跑验证通路，再放开全量。

前缀映射规则：源前缀 A/ → 目的前缀 B/，则 A/a.txt 落成 B/a.txt；目的前缀留空就进根目录。

方案三：镜像回源（做平滑切换用）

如果不能停业务：在 B 账号的 bs-os-test 上配置回源规则指向 A 账号 bs-os 的外网域名。业务先切到 bs-os-test，命中本地直接返回，未命中则实时回源拉取并落一份到本地。

  • 优点：请求无缝切换，用户无感知
  • 缺点：没被访问过的文件永远不会迁过来，首次访问有额外延时
  • 前提：bs-os 需公有读（或回源支持带签名）

正确用法是组合拳：先配回源 → 业务切到 bs-os-test（此时读写已经安全了）→ 后台不紧不慢跑 rclone/US3SYNC 全量兜底 → 全量跑完对账无误后撤掉回源规则 → 下线 bs-os。

—

容易被漏掉的收尾项

这些不会跟着对象一起迁移，要在 B 账号手动重建：

  • Bucket ACL（公有读 / 私有）
  • 生命周期规则、存储类型转换策略
  • 跨域 CORS 配置
  • 自定义域名绑定、CDN 加速配置、防盗链 / Referer 白名单
  • 回源规则、图片处理样式
  • 业务代码里的 bucket 名和域名：bs-os → bs-os-test（名字带 test，如果这其实是生产用途，建议趁迁移改个正式名字）

对账建议留存两份 rclone size 输出（对象数 + 字节数），迁移前后比对一致再做切换。

homepage 是什么

一个自托管导航页，部署在 10.0.0.105 的 /opt/homepage ，五个容器：

容器 端口 作用
homepage 3000 展示导航页，只读配置
homepage-editor 7200 图形化改配置，表单 + 图标选择器
homepage-code-server 8443 文本改配置，浏览器里的 VS Code
homepage-dockerproxy 仅内网 容器状态发现，只读
homepage-editor-restart-proxy 仅内网 仅供 editor 重启容器

核心思路：homepage 自身没有后台，纯靠 ./config/ 下的 YAML 驱动。 把同一个 ./config/ 同时挂给展示端（读）和两个管理端（写）， 改完存盘导航页自动刷新，不用重启任何容器。两个管理端可以同时开着， 它们改的是同一份文件。 

                        读
      ┌──────────────┐ ◀────────────────┐
:3000 │   homepage   │                  │
      └──────┬───────┘           ┌──────┴──────┐
             │ 只读 API          │  ./config/  │
      ┌──────▼───────┐           │   *.yaml    │
      │ dockerproxy  │           └──────▲──────┘
      └──────────────┘                  │ 写
                          ┌─────────────┴─────────────┐
                   :7200  │                           │ :8443
            ┌─────────────┴──────┐          ┌─────────┴──────┐
            │  homepage-editor   │          │  code-server   │
            └─────────┬──────────┘          └────────────────┘
                      │ 仅重启
          ┌───────────▼────────────┐
          │  editor-restart-proxy  │
          └────────────────────────┘

安装

前置

目标机 Ubuntu 26.04 / arm64 / Docker 29.9.1 + Compose v5.6.0 。 三个镜像都有原生 arm64，不需要 registry mirror 。

部署

mkdir -pv /opt/homepage
cd /opt/homepage

# 1. 环境变量。三个密码/地址是必填项，缺了 compose 直接报错退出
cat <<\EOF> .env
# ── 管理端密码（必填，没有默认值，不填 compose 会直接报错退出）────────
CODE_SERVER_PASSWORD=gdtIEI9dvbhMmiHeBbcL

# ── 访问白名单（必填）────────────────────────────────────────────
# homepage v1.0 起强制校验 Host 头。这里必须列出你实际用来访问的
# 「主机:端口」，逗号分隔，少写一个就是白屏 403 且无任何提示。
# 换 IP、加域名、改端口之后都要回来同步这一行。
HOMEPAGE_ALLOWED_HOSTS=10.0.0.105:3000,localhost:3000,127.0.0.1:3000,homepage:3000

# ── homepage 的地址（必填）──────────────────────────────────────
# 给 homepage-editor 用。它拿这一个值干三件事：
#   ① 容器内调 /api/revalidate 让 homepage 重读配置
#   ② 容器内探测 /icons/ 下的图标是否存在
#   ③ 下发给浏览器，当作 Preview 面板那个 iframe 的 src 和「Open ↗」的 href
# ③ 是在*你的浏览器*里执行的，所以这里**不能填 compose 内网服务名**。
# 上游默认值（和它 README、自带 compose.yaml）都是 http://homepage:3000，
# ①② 对而 ③ 必然解析失败 —— Preview 面板是一块灰，连超时提示都不会出现
# （Chrome 的错误页也会触发 iframe 的 load 事件，把提示自己藏掉了）。
# 填什么，就要把对应的「主机:端口」同步进上面的 HOMEPAGE_ALLOWED_HOSTS。
HOMEPAGE_URL=http://10.0.0.105:3000

# ── 端口 ────────────────────────────────────────────────────────
# 注意：本机 8081 已被 nexus 占用、8080 被一个 java 进程占用，别往上撞。
HOMEPAGE_PORT=3000
CODE_SERVER_PORT=8443

# ── 时区 ────────────────────────────────────────────────────────
# 仅对 code-server（Ubuntu 基底）有效。homepage 和 dockerproxy 是 Alpine
# 且不含 tzdata，它们的时区靠 compose 里挂载 zoneinfo 文件解决，改这里没用。
TZ=Asia/Shanghai

# ── code-server 写文件时的属主 ──────────────────────────────────
PUID=1000
PGID=1000
EDITOR_PASSWORD=BTfzTfYDShbizbRWzgVE
EDITOR_PORT=7200
EOF

cat <<\EOF> docker-compose.yml
# homepage 导航页栈 —— 部署在 /opt/homepage，目标机 10.0.0.105
#
#   homepage              :3000   展示端，读 ./config 下的 YAML，存盘即热生效
#   homepage-editor       :7200   图形化改配置（表单 + 图标选择器 + 内置文档）
#   code-server           :8443   文本改配置（浏览器里的 VS Code）
#   dockerproxy           内网    容器状态发现，只读
#   editor-restart-proxy  内网    仅供 editor 重启容器
#
# 安装、组件说明与选型见 GUIDE.org；踩坑记录见 README.org。

name: homepage

services:
  # ── 展示端 ────────────────────────────────────────────────────
  homepage:
    image: ghcr.io/gethomepage/homepage:v2.6.0
    container_name: homepage
    restart: unless-stopped
    ports:
      - "${HOMEPAGE_PORT:-3000}:3000"
    environment:
      # 必填。homepage 强制校验 Host 头，漏填的地址一律白屏 403
      HOMEPAGE_ALLOWED_HOSTS: ${HOMEPAGE_ALLOWED_HOSTS}
      TZ: ${TZ:-Asia/Shanghai}
    volumes:
      - ./config:/app/config
      # 背景图和自定义图标必须挂到 /app/public 下，homepage 只从这里提供静态文件。
      # 放进 config/ 里是取不到的（404），因为两者之间没有任何链接。
      # 引用时写 /images/xxx.jpg 和 /icons/xxx.png。换文件后要重启 homepage
      - ./config/images:/app/public/images
      - ./config/icons:/app/public/icons
      # Alpine 基底不含 tzdata，TZ 要配合整个 zoneinfo 目录才生效
      - /usr/share/zoneinfo:/usr/share/zoneinfo:ro
      - /usr/share/zoneinfo/Asia/Shanghai:/etc/localtime:ro
    networks:
      - homepage
    depends_on:
      - dockerproxy
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:3000/api/healthcheck"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 40s

  # ── 图形化管理端 ──────────────────────────────────────────────
  homepage-editor:
    image: ghcr.io/jchisholm59/homepage-editor:latest
    container_name: homepage-editor
    restart: unless-stopped
    ports:
      - "${EDITOR_PORT:-7200}:7200"
    environment:
      # 必填，且必须是浏览器能访问的地址：Preview 面板的 iframe 直接用它。
      # 填 compose 服务名的话容器内能通、浏览器打不开。
      HOMEPAGE_URL: ${HOMEPAGE_URL:?请先在 .env 里设置 HOMEPAGE_URL（浏览器能访问的地址）}
      HOMEPAGE_CONTAINER: homepage
      DOCKER_PROXY: http://editor-restart-proxy:2375
      EDITOR_PASSWORD: ${EDITOR_PASSWORD:?请先在 .env 里设置 EDITOR_PASSWORD}
      TZ: ${TZ:-Asia/Shanghai}
    volumes:
      - ./config:/config
      # 每次保存前自动备份到这里，可在界面 Backups 页回滚
      - ./editor-backups:/backups
      - /usr/share/zoneinfo:/usr/share/zoneinfo:ro
      - /usr/share/zoneinfo/Asia/Shanghai:/etc/localtime:ro
    networks:
      - homepage
    depends_on:
      - editor-restart-proxy
    # 覆盖镜像自带的探测：原版不带凭据，设了密码必然 401。$$ 交给容器内 shell 展开
    healthcheck:
      test:
        - CMD-SHELL
        - >-
          wget -qO- --header="Authorization: Basic $$(printf 'x:%s' "$$EDITOR_PASSWORD" | base64)"
          http://127.0.0.1:7200/api/info >/dev/null || exit 1
      interval: 60s
      timeout: 5s
      retries: 3
      start_period: 30s

  # ── 文本管理端 ────────────────────────────────────────────────
  code-server:
    image: lscr.io/linuxserver/code-server:4.141.0-ls371
    container_name: homepage-code-server
    restart: unless-stopped
    ports:
      - "${CODE_SERVER_PORT:-8443}:8443"
    environment:
      PUID: ${PUID:-1000}
      PGID: ${PGID:-1000}
      TZ: ${TZ:-Asia/Shanghai}
      PASSWORD: ${CODE_SERVER_PASSWORD:?请先在 .env 里设置 CODE_SERVER_PASSWORD}
      DEFAULT_WORKSPACE: /config/workspace/homepage
    volumes:
      # code-server 自身状态（插件、设置）
      - ./code-server:/config
      # 与 homepage 共享同一份配置目录
      - ./config:/config/workspace/homepage
    networks:
      - homepage

  # ── 容器发现代理（只读）───────────────────────────────────────
  # 替代直接给 homepage 挂 docker.sock：socket 上的 :ro 只防写文件，
  # 不限制 API 调用，这一层才真正收窄「能调哪些 API」。
  dockerproxy:
    image: tecnativa/docker-socket-proxy:v0.5.0
    container_name: homepage-dockerproxy
    restart: unless-stopped
    environment:
      CONTAINERS: 1
      POST: 0
      IMAGES: 0
      NETWORKS: 0
      VOLUMES: 0
      SERVICES: 0
      TASKS: 0
      NODES: 0
      SECRETS: 0
      CONFIGS: 0
      SWARM: 0
      SYSTEM: 0
      INFO: 0
      EXEC: 0
      BUILD: 0
      COMMIT: 0
      PLUGINS: 0
      AUTH: 0
      DISTRIBUTION: 0
      SESSION: 0
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /usr/share/zoneinfo:/usr/share/zoneinfo:ro
      - /usr/share/zoneinfo/Asia/Shanghai:/etc/localtime:ro
    networks:
      - homepage
    read_only: true
    tmpfs:
      - /run
      - /tmp

  # ── 重启代理（仅供 editor）────────────────────────────────────
  # 权限比上面那个大：能重启/停掉本机任意容器。只为 editor 的
  # 「Restart Homepage」按钮而存在，不需要可连同 DOCKER_PROXY 一起删。
  editor-restart-proxy:
    image: tecnativa/docker-socket-proxy:v0.5.0
    container_name: homepage-editor-restart-proxy
    restart: unless-stopped
    environment:
      POST: 1
      ALLOW_RESTARTS: 1
      CONTAINERS: 1
      EVENTS: 0
      IMAGES: 0
      NETWORKS: 0
      VOLUMES: 0
      EXEC: 0
      BUILD: 0
      INFO: 0
      SYSTEM: 0
      AUTH: 0
      SECRETS: 0
      CONFIGS: 0
      SWARM: 0
      NODES: 0
      TASKS: 0
      SERVICES: 0
      PLUGINS: 0
      COMMIT: 0
      DISTRIBUTION: 0
      SESSION: 0
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /usr/share/zoneinfo:/usr/share/zoneinfo:ro
      - /usr/share/zoneinfo/Asia/Shanghai:/etc/localtime:ro
    networks:
      - homepage
    read_only: true
    tmpfs:
      - /run
      - /tmp

networks:
  homepage:
    name: homepage
    driver: bridge
EOF

chmod 600 .env



# 2. 校验语法
docker compose config -q && echo "语法 OK"

# 3. 启动
docker compose up -d

# 4. 看状态，homepage 和 homepage-editor 应为 (healthy)
docker compose ps

.env 里必须自己填的三项：

变量 填什么
CODE_SERVER_PASSWORD 任意强密码
EDITOR_PASSWORD 任意强密码，用户名随便填
HOMEPAGE_URL *浏览器*能访问的 homepage 地址，如 http://10.0.0.105:3000

另有一项 HOMEPAGE_ALLOWED_HOSTS ，要列出所有你实际用来访问的 「主机:端口」，逗号分隔。homepage 强制校验 Host 头， 漏一个就是白屏 403且页面不给任何提示 。换 IP、加域名、改端口之后都要回来同步这一行。

HOMEPAGE_URL 里填的地址也必须出现在这个白名单里 —— editor 访问 homepage 时发出的 Host 头就是它。

组件说明

homepage —— 展示端

ghcr.io/gethomepage/homepage:v2.6.0 ，端口 3000 。

只读 ./config/ 下的 YAML ，存盘即热生效，不需要重启。 两个例外：*新加的自定义图标和背景图要重启才认* （Next.js 静态文件）， editor 界面上的「Restart Homepage」按钮就是干这个的。

配置文件：

文件 作用
settings.yaml 标题、主题、语言、分组布局（列数）
services.yaml 服务卡片，可带容器状态
bookmarks.yaml 纯链接书签，不探活
widgets.yaml 顶部的资源、搜索、时间小组件
docker.yaml 容器发现源，指向 dockerproxy

缩进必须 2 空格 ，层级是「分组 → 服务名 → 属性」。缩进错了页面会整片空白 且不报任何错。要给服务卡片加容器状态徽章， server 和 container 两项必须一起写： 

- 基础设施:
    - Nexus:
        href: http://10.0.0.105:8081
        description: 制品仓库
        icon: nexus.png
        server: my-docker        # 对应 docker.yaml 里的键名
        container: nexus         # 容器真实名字

容器真实名字用 docker ps --format '{{.Names}}' 查。 图标名去 https://github.com/walkxcode/dashboard-icons 检索，填 xxx.png 。

homepage-editor —— 图形化管理端

ghcr.io/jchisholm59/homepage-editor:latest ，端口 7200 ，HTTP Basic 认证 （用户名随便填，密码是 EDITOR_PASSWORD ）。

日常加服务、挑图标、配 widget 用它。有表单和内置文档，不用记字段名。 三个值得知道的点：

  • 它保证不破坏你手写的注释 。保存时是把改动 merge 进已解析的 YAML Document 再序列化，而不是重写整个文件。这是选它的决定性理由
  • 每次保存前给你看 diff ，并自动备份到 ./editor-backups/<时间戳>/ ， 界面 Backups 页可回滚
  • 非法 YAML 返 400 拒绝；文件在你编辑期间被别人改过（ baseMtime 过期） 返 409 拒绝。两种情况文件都完好

右上角「Preview」能在编辑器旁边开一个 homepage 实时预览。 它用的是 HOMEPAGE_URL ，所以那个变量必须填浏览器能访问的地址。

code-server —— 文本管理端

lscr.io/linuxserver/code-server:4.141.0-ls371 ，端口 8443 。

批量改、看 diff 、处理 editor 覆盖不到的写法时用它。本质是个带 YAML 高亮的 VS Code ，缩进错了当场能看出来。

它以 PUID / PGID 身份写文件，homepage 以 root 读，不会有属主冲突。 自身状态（插件、设置）存在 ./code-server/ 。

dockerproxy —— 容器发现代理

tecnativa/docker-socket-proxy:v0.5.0 ，不发布端口，只在 compose 内网可达。

homepage 要显示容器状态徽章就得访问 Docker API 。直接给它挂 docker.sock 也能跑，但 socket 上的 :ro 只限制对文件本身的写， 完全不限制 API 调用 —— 照样能 POST /containers/create 挂载宿主目录、 起特权容器，等于把宿主 root 交出去。

这一层代理把「能调哪些 API 」真正收窄：只放行 CONTAINERS: 1 ， 其余全部显式关死。 POST: 0 意味着连 start / stop / exec 都发不出去， 即使 homepage 被攻破，拿到的也只是一个容器列表。 它自己还加了 read_only: true 和 tmpfs ，转发代理不需要可写根文件系统。

editor-restart-proxy —— 重启代理

同一个镜像，但 权限比上面那个大得多 ： POST: 1 和 ALLOW_RESTARTS: 1 ， 意味着它能重启或停掉本机任意容器，包括 nexus 。

它只换来一个功能：editor 界面上的「Restart Homepage」按钮。 不需要这个便利的话，把本服务连同 editor 的 DOCKER_PROXY 环境变量 一起删掉即可 ，editor 其余功能完全不受影响，要重启时手敲 docker compose restart homepage 就是了。

选型参考

为什么是 homepage

静态配置、无数据库、单容器、有容器状态探测和 widget 生态。 配置是纯文本意味着最坏情况永远能手改回来，不会被一个坏掉的管理端锁死。

为什么两个管理端并存

它们不是冗余，是互补：

  • homepage-editor 懂字段语义，适合加服务、挑图标、配 widget
  • code-server 什么都能改，适合批量操作和 editor 覆盖不到的写法

而且图形化管理端是这套栈里最新、最小的一环（见下）， 留一个纯文本入口是兜底 —— editor 出问题时不至于没法改配置。

图形化管理端的候选对比

gethomepage 官方不提供后台。2026-10-23 调研时的同类项目：

项目 星 最后更新 许可 预构建镜像 备注
jchisholm59/homepage-editor 2 2026-10-22 MIT GHCR，含 arm64 保留注释、保存前 diff、备份
hyprlab/homepage-gui 4 2026-10-02 AGPL ? 只管 services.yaml
BangerTech/homepage-ui 10 2026-09-08 无 需自行 build 功能全，但没有许可证
hoiber/homepage-config-gui 9 2025-09-12 GPL-3 有 停更一年多
hoiber/homepage-config-editor 5 已归档 — — 已死

决定性理由是 保留 YAML 注释 。本项目的配置文件里写满了说明性注释， 多数 GUI 编辑器保存时会把整个文件重写一遍，注释全部消失。 实测 homepage-editor 新增一个服务后 diff 只有 6 行新增， 注释 5 → 5 行，空行和文件属主均未变。

选它的代价要清楚 ：2 星 / 0 fork / 0 open issue ，2026-10-03 才建仓 （2026-10-24 复查数字未变）。核心的保存逻辑实测扎实，但出问题基本 没有社区可问，而且已经遇到过一次上游默认配置就是错的情况。 好在配置是纯文本，最坏情况退回 code-server 手改。

它按 Homepage v1.13.2 构建而本机跑 v2.6.0 ，实测解析和保存都正常、 中文分组名也没问题，但新版本独有的字段它的表单里可能没有 —— 遇到这种情况用 Files 标签页或 code-server 直接写。

为什么文本管理端选 code-server 而不是 Filebrowser

homepage 的 YAML 缩进错了页面会整片空白且不报错。 VS Code 的 YAML 高亮能当场看出来，纯文件管理器不能。

其它决策

  • 镜像 pin 死版本 ，不用 :latest 。版本号是部署当天从镜像 label 实测取的。升级走 docker compose pull ，心里有数
  • 密码只在 .env 里 ， .gitignore 已排除。compose 里用 ${XXX:?...} 写法，没设置就直接报错退出，不会静默起一个无密码服务
  • 时区靠挂载 zoneinfo ，不是只设 TZ 。镜像是 Alpine 基底不含 tzdata ， 只设 TZ 会静默回落 UTC 。细节见 README.org 坑一

没做的事

  • 没有 HTTPS 。全是明文 HTTP ，管理端密码也是明文传输。仅限内网使用
  • 没有备份机制。 restart: unless-stopped 够用；建议把 ./config/ 纳入 git 托管（ .gitignore 已配好，会排除 .env 和 code-server 状态）
  • 没有接入统一认证

# 顶部信息小组件（info widgets）。文档：https://gethomepage.dev/configs/info-widgets/
#
# 注意区分：这里是「信息小组件」，独立存在、和具体服务无关。
# services.yaml 里每个服务下面也能写 widget，那叫「服务小组件」，
# 是去调那个服务自己的 API 取数据，两者不是一回事。

- greeting:
    text_size: xl
    text: Home Lab

- datetime:
    text_size: xl
    locale: zh-CN
    format:
      dateStyle: long
      timeStyle: short
      hour12: false
      timeZone: Asia/Shanghai

# 宿主机资源。没开 cputemp：本机 /sys/class/thermal 下只有 cooling_device*，
# 没有 thermal_zone*，开了也取不到温度，只会空着
- resources:
    label: 宿主机
    cpu: true
    memory: true
    disk: /
    uptime: true
    units: metric

# 杭州天气。用 openmeteo 而不是 openweathermap / weatherapi —— 它不需要 API key。
# 经纬度是杭州市区；数据由 homepage 服务端去取，所以要容器能出网（已实测可达）
- openmeteo:
    label: 杭州
    latitude: 30.2741
    longitude: 120.1551
    units: metric
    cache: 5
    timezone: Asia/Shanghai

- search:
    provider: baidu
    target: _blank

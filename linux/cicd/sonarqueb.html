SonarQube 介绍

SonarQube 是一款用于代码质量管理的开源工具，它主要用于管理源代码的质量。 通过插件形式，可以支持众多计算机语言，比如 java, C#, go，C/C++, PL/SQL, Cobol, JavaScrip, Groovy 等。sonar可以通过PMD,CheckStyle,Findbugs等等代码规则检测工具来检测你的代码，帮助你发现代码的漏洞，Bug，异味等信息。

Sonar 不仅提供了对 IDE 的支持，可以在 Eclipse和 IntelliJ IDEA 这些工具里联机查看结果；同时 Sonar 还对大量的持续集成工具提供了接口支持，可以很方便地在持续集成中使用 Sonar。

  • 官方网站：http://www.sonarqube.org/
  • 下载地址：https://www.sonarqube.org/downloads/
  • Github 地址: https://github.com/SonarSource/sonarqube

架构和集成

  • 支持的语言：Supported languages
  • 服务端组件：Server components

核心架构：三个 Java 进程 + 外部依赖

SonarQube Server 实例本身由一个 JVM 父进程 Sonar（负责管理和监控下面三个子进程的可用性）拉起三个独立的 Java 进程：

进程 职责 堆配置项
Web Server 提供 Web UI 和 Web API；ES 索引损坏时负责重建索引 sonar.web.javaOpts
Compute Engine(CE) 从数据库中的任务队列取出扫描报告，计算度量、问题、质量门结果并落库 sonar.ce.javaOpts
Search Server(Elasticsearch) 维护数据库的索引副本，支撑搜索和过滤 sonar.search.javaOpts

Web 和 CE 两个进程都会向 ES 和数据库写入，并各自保证数据一致性。

一次完整分析需要的三类组件

  1. Server（上述三进程）
  2. Database — 存储代码质量与安全的度量/问题、实例配置，以及由 Scanner 写入、CE 消费的分析报告任务队列
  3. Scanner — 运行在构建机或 CI 上的 SonarScanner（Maven/Gradle/CLI/.NET 等），负责分析源码并上传报告

  • SonarQube Server —— 自托管，就是传统意义上的 SonarQube，分四个 Edition（下面详述）

SonarQube 分两种版本: LTA 和非 LTA

Sonar 在 2023 年正式把 LTS (Long-Term Support) 改名为 LTA (Long-Term Active)。原 9.9 LTS 直接变成 9.9 LTA。改名原因是"support"有歧义——商业技术支持（Support）和"受支持的版本"两个意思混在一起容易引起误解。现在官方文档和下载页一律用LTA。

SonarQube Server 每两个月发布一个版本，一年 6 个，其中 2 个为 LTA（Long-Term Active，2023 年前称 LTS）版本。LTA 是功能完整的稳定版本，自发布起提供 12 个月的补丁支持（Enterprise/DCE 客户购买 Enterprise Support 可延长至 18 个月），EOL 后再提供 6 个月技术支持，适合无法频繁升级的组织。

  • 2026 年起：一年 2 个（2026.1 LTA、2026.5 LTA）

另外，LTA 概念只适用于 SonarQube Server 的商业版。Community Build 是滚动发布（约每月一版），没有 LTA 分支，也不发补丁——出了问题只能升到下一个 build。

  • 当前 LTA 是 2026.5（2026-09-29 发布），最新补丁 2026.5.2，活跃支持到 2027-10-01，安全支持到 2028-03-01

安装环境准备

硬件要求

规模 定义 RAM
小规模 Community Build / Developer，≤ 1M LOC 4 GB
大规模 单节点 Enterprise ≤ 50M LOC，或 DCE 的单个节点 16 GB
  • 处理器：64 位系统
  • 磁盘：必须是读写性能优秀的盘（Search 节点上 SSD 相比 HDD 性能差距显著）；容量取决于分析的代码量

Web 和 Compute Engine 进程的默认堆大小在所有 Edition 上都调高了。如果你的实例本来就贴着内存上限跑，或者容器设了固定内存配额，升级前必须加内存，否则起不来。

系统内核优化

因为内嵌 Elasticsearch，主机必须满足 ES 的 production mode 要求：

参数 最小值
vm.max_map_count 524288
fs.file-max 131072
用户打开文件数 (ulimit -n) 131072
用户线程/进程数 (ulimit -u) 8192 
# 检查当前值：
sysctl vm.max_map_count
sysctl fs.file-max
ulimit -n
ulimit -u

# 临时生效（root）：
#mv.max_map_count 用于限制一个进程可以拥有的 VMA (虚拟内存区域)的数量
sysctl -w vm.max_map_count=524288
#设置系统最大打开的文件描述符数
sysctl -w fs.file-max=131072
#每个用户可以打开的文件描述符数
ulimit -n 131072
#每个用户可以打开的线程数
ulimit -u 8192

# 永久生效：
# 内核参数 —— 写入 /etc/sysctl.d/99-sonarqube.conf
cat <<EOF> /etc/sysctl.d/99-sonarqube.conf
vm.max_map_count=524288
fs.file-max=131072
EOF

# 用户限制 —— 写入 /etc/security/limits.d/99-sonarqube.conf
cat <<EOF> /etc/security/limits.d/99-sonarqube.conf
sonarqube   -   nofile   131072
sonarqube   -   nproc    8192
EOF


#用 systemd 托管的话 limits.conf 不生效，必须写在 unit 文件的 [Service] 段里
LimitNOFILE=131072
LimitNPROC=8192

说明: /etc/postgresql/1X/main/pg_hba.conf 

格式:TYPE DATABASE USER ADDRESS METHOD
METHOD有如下值可选
md5： 执行MD5身份验证以验证用户的密码。
peer：从操作系统获取客户端的操作系统用户名，并检查它是否与请求的数据库用户名匹配。这仅适用于本地
连接。
trust：允许无条件连接，允许任何PostgreSQL用户身份登录，而无需密码或任何其他身份验证。
reject：拒绝任何条件连接，这对于从组中“过滤掉”某些主机非常有用。
scram-sha-256：执行SCRAM-SHA-256身份验证以验证用户的密码。
password：要提供未加密的密码以进行身份••验证。由于密码是通过网络以明文形式发送的，因此不应在不
受信任的网络上使用。
gss：使用GSSAPI对用户进行身份验证，这仅适用于TCP / IP连接。
sspi：使用SSPI对用户进行身份验证，这仅适用于Windows。
ident：通过联系客户端上的ident服务器获取客户端的操作系统用户名，并检查它是否与请求的数据库用户
名匹配。 Ident身份验证只能用于TCP/IP连接。为本地连接指定时，将使用对等身份验证。
ldap：使用LDAP服务器进行身份验证。
radius：使用RADIUS服务器进行身份验证。
cert：使用SSL客户端证书进行身份验证。
pam：使用操作系统提供的可插入身份验证模块（PAM）服务进行身份验证。
bsd：使用操作系统提供的BSD身份验证服务进行身份验证。

# 先确认当前有什么：
root@ubuntu2604:~# locale -a | grep -i utf

LimitNPROC=8192
TimeoutStartSec=5
Restart=always
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now sonarqube.service
systemctl status sonarqube.service

方法2-通过 Docker compose 部署

#先优化内核参数
# 容器里的 Elasticsearch 用的是宿主机内核，所以 vm.max_map_count 必须在宿主机上调：

sudo sysctl --system

# 验证
sysctl vm.max_map_count

mkdir sonarqube
cd sonarqube
cat <<\EOF> docker-compose.yml
services:
  db:
    #image: public.ecr.aws/docker/library/postgres:18
